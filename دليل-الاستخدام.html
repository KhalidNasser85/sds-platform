١) مقدمة ومكوّنات المنصة

منصّة «وصل» تُدير الربط الآمن بين الشركات ولوحتها المركزية: لكل شركة عامل (Agent) يفتح قنوات أنفاق (نفق سريع عبر TryCloudflare) لخدماتها، ويُوقّع حالةً (نبضًا) بشكل دوري، وتسجَّل الشركات في سجل موقّع مركزي يحرس دورياً ضد التلاعب والتدرُّج.

المكوّنات

  • لوحة التحكم المركزية (Center) — واجهة الويب المحلية للعمليات والدخول برُتَب.
  • العامل (Agent) — يعمل لدى كل شركة: قنوات + نبض موقّع + صيانة.
  • قنوات الأنفاق — web · mobile · ops (صيانة) · db (قاعدة بيانات، اختياري).
  • السجل الموقّع (Registry) — قائمة الشركات بإصدار رتيب وتوقيع، مع حارس تدرّج وعدّاد صلاحية.
  • المراقبة (MON) — تُحدَّث تلقائيًا كل 15 ثانية؛ تنبيه إن تأخر النبض عن 40 ثانية أو خَبُث التوقيع.
  • مُصدِر الحالة (Gist) — جهة خارجية لنشر الحالة الموقّعة (اختياري للنشر العام).

٢) الدخول والأدوار

افتح المتصفح على /login وأدخل اسم المستخدم وكلمة المرور.

قواعد الأمان

  • بعد 5 محاولات فاشلة يُقفَل الدخول مؤقتًا (رد 429).
  • عند أول دخول (أو عند طلب المشغِّل) تظهر شاشة تغيير كلمة المرور إلزاميًا قبل أي إجراء.
  • الجلسات قصيرة العمر مع كوكيز HttpOnly؛ يُسجَّل كل دخول/خروج في السجل.

٣) لوحة التحكم

العمودماذا يعرض

٤) المراقبة (MON)

صفحة /monitor/:code تعرض بطاقة MON للشركة وتتحدّث كل 15 ثانية.

الدورة

  1. العامل ينشر نبضًا موقّعًا كل 30 ثانية (نسخة محلية: companies\<code>\logs\status.json).
  2. المركز يتحقق من التوقيع بمفتاح الشركة العام ومن عمر النبض.
  3. إن لم يصل نبض صحيح خلال ≤ 40 ثانية → حالة ALERT.

قراءة البطاقة

الحقلالمعنى
النبض / العمرزمن آخر نبض و«عمره» بالثواني (≤40 طبيعي)
إعادة التشغيلعداد restart_count — يزداد عند كل تشغيل للعامل (طبيعي)
نسخة الحالةرقم الحالة الموقّعة الحالية
التوقيعصحيح أو حالة الخلل (خاطئ/منتهي/…)
⚠ لوح = تنبيه. تحقق من القنوات أدناه (يعمل/متوقف) ومن الخدمات المُعلنة، ثم أعد تشغيل العامل (قسم ٦).

التصرف عند ALERT

  1. افتح صفحة الشركة في اللوحة ← زر مراقبة لتشخيص القناة المتعثرة.
  2. إذا كانت الخوادم المحلية حيّة، أعد فتح النفق من اللوحة (تشغيل/إعادة) أو تلقائيًا عبر العامل.
  3. إذا عاد النبض، ينعكس الوضع إلى معافى تلقائيًا؛ عداد إعادة التشغيل يزداد — سلوك مقصود ومقيّد بالسجل.

٥) إدارة الشركات

Onboarding شركة جديدة (مدير)

زر «Onboard جديد» — يُنفَّذ محليًا على جهاز المشغِّل (وليس عبر النفق العام):

١ توفير (Provision)←٢ تسجيل (Register)←٣ تفعيل (Activate)

توفير الإعداد والمفاتيح والخزنة (مفتاح RSA-2048 لكل شركة) ثم تسجيل وتفعيل في السجل الموقّع. حقول اللوحة:

  • الرمز (مثل DEV02) · الاسم · البيئة
  • منافذ محلية: ويب (افتراضيّ 8100) · جوال (8200) · صيانة (9555) · وصل (9550)
  • تفعيل قاعدة البيانات (اختياري، قناة db على 9446)
✔ بعد النجاح تظهر رسالة «الشركة جاهزة (config/keys/vault + مسجلة وفعّالة)» وتحدَّث اللوحة.

أزرار القنوات

الزرالمفعول
تشغيل / إيقاففتح أو إغلاق قناة الويب (مع حفظ رابط النفق)
إعادةإغلاق وفتح القناة (أسرع علاج للانقطاع الخارجي)
فحصتحقق ٦ نقاط: الخدمة المحلية، عملية النفق، الرابط العام، تطابق مصدِّر الحالة، سالمة نقطة الصحة، وتوقيع الحالة
نشرإعادة نشر عنوان القناة إلى جهة خارجية (Gist)

الصيانة (Ops)

عمليات مرخّصة: حالة/إعادة تشغيل الخدمة، حالة/إعادة تشغيل النفق، فحص الصحة، قائمة السجلات، سحب سجل، حالة القرص.

قاعدة البيانات (DB)

اختر تقريرًا معتمدًا (§7)، أدخل المعاملات، شغّله، وصَدِّر CSV / XLSX / PDF. العمليات المرخّصة (allowlist محدودة مثل license.count) تظهر لمن يملك db.op.

الخزنة (Vault)

عرض محدود من صلاحيات المدير: حالة الخزنة، وضع/تحديث قيمة سرية، تدوير المفتاح (مع نسخة احتياطية مشفّرة بمفتاح الاسترداد أولًا)، تصدير. التخزين AES-256-GCM محليًا.

الترخيص (L1)

إنشاء/تجديد/تخفيض/تعليق/سحب/إنهاء الترخيص؛ توقيعه ثابت بالمفتاح المركزي ولا يُعاد تخليق إلّا عند تغيير الحقول الجوهرية (مثال MS-1001-AUTO). تخفيض المقاعد مع مستخدمين نشطين مرفوض (E_LICENSE_DOWNGRADE).

٦) العامل والاتصال

لكل شركة مجلد companies\<code>\ يحتوي الإعداد والمفاتيح والخزنة والسجلات.

أوامر العامل

node agent\agent.js --company <CODE> --command run       # تشغيل: قنوات + نبض موقّع
node agent\agent.js --company <CODE> --command stop      # إيقاف نظيف
node agent\agent.js --company <CODE> --command selftest   # فحص ذاتي (مفاتيح/سجل/قنوات) — 45/45
node agent\agent.js --company <CODE> --command seed      # حقن الأسرار من env إلى الخزنة

ماذا يفعل عند التشغيل

  • يفتح القنوات المحلية (web 8100، mobile 8200، ops 9555، واختياريًّا db 9446).
  • يُوقّع الحالة كل 30 ثانية إلى المِرآة المحلية companies\<code>\logs\status.json (وتتضمن النبض، نسخة الحالة، الخدمات، عداد إعادة التشغيل، والتوقيع).
  • يزيد عداد logs\restart_count.txt عند كل تشغيل — يظهر في اللوحة وMON.
  • يعيد فتح النفق ذاتيًا عند الانقطاع ويُحافظ على الرابط الخارجي.
⚠ الخطأ fail 5/5 مع الصحّة المحلية جيدة = النفق الخارجي بحاجة لإعادة؛ ابدأ من لوحة المركز (إعادة) أو أعد تشغيل العامل.

٧) السجل الموقّع والتهجير

السجل في registry\registry.json (+ state.json + switchover.json) بصيغة موقّعة:

الميزةالسلوك
إصدار رتيبكل نشر يرفع version (الحالي v6)
حارس التدرّجأي محاولة رجوع لإصدار أقدم تُرفض (E_ROLLBACK_REJECTED)
انتهاء الصلاحيةبعد تجاوز نافذة الصلاحية تظهر حالة expired ويُعاد النشر من جديد
التلاعبتغيير أي حقل يكسر التوقيع → invalid ويرفض

حالة الاعتماد عبر GET /api/registry: verify.status=valid وكل الشركات الأعضاء active.

تهجير الناشر (VB Switchover)

عند تبديل مزوّد الحالة من نظام قديم إلى العامل الجديد: يتوقف الكاتب القديم أولًا، ثم يعتمد sds-agent ككاتب واحد — لا كاتبين في نفس الوقت. يُسجَّل ذلك في registry\switchover.json مع حدث vb.switchover في سجل الشركة.

٨) الأمان والعمليات اليومية

الأصول السرية

  • مفتاح توقيع L1 وGist token: من البيئة/الخزنة فقط، لا عبر الأنفاق العامة ولا في الملفات المتتبَّعة.
  • خزنات الشركات companies\*\vault خارج التحكم بالمصدر (مُستثناة تلقائيًا).
  • المنافذ الداخلية (9555/9550/9446) غير مكشوفة للعموم؛ الجهة الخارجية فقط روابط القنوات العامة.

فحص يومي مقترح

  1. GET /api/monitor — كل الشركات OK، heartbeat_age_s ≤ 40، signature=valid.
  2. GET /api/registry — verify.status=valid والشركات active.
  3. راجع سجلات الأحداث: vault\center-logs\audit.jsonl و companies\<code>\logs\audit.jsonl.
  4. افحص التقرير الصحي للقنوات (زر «فحص») دوريًّا للشركات المهمة.

الإيقاف الآمن والاستعادة

إيقاف عامل: --command stop ثم run للعودة (يستأنف النبض خلال 30 ثانية وتُعاد فتح الأنفاق ذاتيًا). إيقاف المركز: أنهِ node center.js؛ السجل الموقّع محفوظ على القرص ولا يفقد شيئًا.
